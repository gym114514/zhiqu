# 知趣：可执行的学习体验脚本

## v2 更新（当前）

当前采用按知识目标选择与组合活动的 v2 协议，保留 v1 导入兼容。五个入口涵盖机制、概念、方法与证据。详见 [脚本 v2 说明](SCRIPT_FORMAT.md)。下述固定流程是首版设计记录；新生成器及播放器的活动顺序由 steps 决定。

## 首版设计记录

面向成年人探索陌生领域。每次约 5–10 分钟，目标是用一个概念解释一个新例子，唤起进一步探索的兴趣。时长、概念数量和步骤均为产品假设，不宣称是通用神经科学定律。

首版包括三个完整示例：星光与时间、独立概率、历史证据。它们使用相同的脚本播放器，分别验证数值操作、随机模拟、证据比较三种互动。自由主题可通过复制生成指令与导入 JSON 使用任意支持联网的 AI；配置服务端 AI 后可直接生成。

## 内容编排

1. 收窄主题：把大主题变为一个具体入口问题，写出可观察的学习目标。
2. 查资料：列出关键事实与来源、常见误解、简化条件。独立 AI 审阅不能替代资料核对。
3. 先设计迁移任务：在一个新情境检验目标，再倒推所需概念和示例。
4. 编排体验：预测 → 操作或对照 → 解释 → 迁移 → 自我表达 → 总结。
5. 审查：事实依据、术语负担、类比边界、问题与目标一致性、每个答案的针对性反馈。
6. 校验与播放：结构化脚本必须经过 Zod 校验，不能执行用户导入的代码。

## 回答分支

- 首次判断无倒计时、无分数。选项提交后显示对应反馈。
- 不知道时可请求提示；答错后可改选，也可带着线索继续。
- 迁移环节记录是否选对、是否借助提示或先前反馈，仅供完成页准确描述本次体验，不推断学科掌握程度。
- 自由表达保留在页面内存，不自动上传、不用关键词匹配判定理解；展示自查要点及可展开示范。
- 刷新或退出会清除当前进度。首版不保存个人学习记录。

## 生成实现

`lib/lesson.ts` 定义运行时 schema、模型 JSON Schema 以及可复制的工作流提示词。`lib/lessons.ts` 提供三个示例。`app/page.tsx` 是通用播放器和脚本工坊。`app/api/generate/route.ts` 提供可选服务端流程：

1. Responses API 强制 web_search，收集回答中的来源引用。
2. 基于事实底稿生成结构化脚本。
3. 结合底稿审校并返回修正脚本。
4. 用 Zod 检查字段、长度、来源 URL、每题唯一最佳答案等；来源限定为检索阶段实际返回的链接。

仅服务端读取 `OPENAI_API_KEY` 与 `OPENAI_MODEL`，两者齐全才显示直接生成。模型需支持 Responses API、web_search 与结构化输出。密钥不进入客户端。调用设有超时，并支持取消；错误不把服务端密钥或原始供应商响应返回前端。

直接生成的真实模型路径在未提供密钥的环境无法端到端验证。来源存在也不等于每个表述都准确；生成内容仍需人工核对。公开提供模型生成前需补充可靠的账户、用量控制及内容审查，当前原型按私有使用设计。

## 内容边界

- 光年是距离；光程延迟不证明恒星已经死亡。示例限近邻、距离近似恒定的模型。
- 硬币公平且各次独立才有下一次 50%；有限模拟用于观察，不是证明。模拟记录最多保留最近 5000 次。
- 史料示例明确虚构；作者身份不是判定真假依据。迁移题只选合理调查路径，不宣称唯一历史解释。
- 导入脚本只做结构校验，展示“内容与来源待核对”。文字由 React 转义；链接仅允许 HTTPS。来源链接不会被后台自动访问。

## 后续如何验证学习效果

小规模对比“同样事实的短文”与“探索脚本”：比较新情境解释质量、一天后的回想与是否愿意继续探索。不要仅用时长、点击次数或主观懂了评分替代学习效果；初次只测可用性，收集在哪一步困惑或厌烦。当前版本没有做用户研究或效果测量。

## 研究依据与限制

- [Karpicke & Blunt, 2011](https://pubmed.ncbi.nlm.nih.gov/21252317/)：科学文本学习实验中，提取练习对概念理解和推断有益。这不意味着本产品已证实有效。
- [Brod et al., 2019](https://www.nature.com/articles/s41539-019-0056-y)：先预测提高了该实验中的好奇心，但组间整体记忆表现没有显著差异；不能简单承诺“猜一次就记得更好”。
- [Deslauriers et al., 2019](https://doi.org/10.1073/pnas.1821936116)：大学物理课堂实验中，主观学习感受和实际测验表现可能不同，支持使用实际任务检查理解的设计动机。
